Part 01 ｜ 選題動機

選題動機與想解決的問題

目標使用者族群

1. 喜愛海景與特色手沖咖啡的慢活旅人。
2. 需要插座、Wi-Fi 沉浸敲筆電做設計的遠端工作者。
3. 想提前預約窗景席、預防現場候位落空的假日訪客。

傳統獨立咖啡店痛點

・傳統紙本菜單更換成本高，售完品項無法即時通知顧客。
・電話訂位容易漏單或超額預約，缺乏即時防呆。
・顧客初次造訪常在琳瑯滿目的手沖單品豆單前無所適從。

嶼光珈琲解決方案

・互動式「今日命定咖啡推薦測驗」，3 題快速為客人找到心頭好。
・提供線上預約與外帶點餐結帳模擬。
・打造「後台資料管理 CRUD 系統」，菜單、庫存售完狀態與訂位即時雙向聯動！

Live Demo：沉浸式海景首頁 ＆ 命定測驗

今日命定咖啡推薦測驗 (Coffee Matchmaker)

・Q1 烘焙偏好：淺焙（花果香）、中焙（焦糖堅果）、深焙（醇厚黑巧）。
・Q2 口感質地：澄澈黑咖啡、絲滑燕麥奶、微氣泡特調。
・Q3 當下狀態：激發專注靈感、悠閒放空眺望、療癒犒賞自己。
・動態配對演算法：由答案即時算出最匹配的單品手沖或招牌拿鐵，並附風味引言。
・高轉化體驗：顧客可直接在測驗結果點擊「加入外帶訂單」，無縫銜接結帳。

設計考量

許多初次光顧獨立精品咖啡廳的顧客會有「點單恐懼症」。我們透過遊戲化的問答介面，讓專業的咖啡風土語言轉化為親民的生活情境，大幅提升互動參與率。

Part 04 ｜ 核心展示 (三)

Live Demo：線上座席預約系統 (時段防呆機制)

顧客端預約功能特色

・預約人資料與人數：可選 1 人享受獨處至 5 人以上聚會。
・即時日期限制 (防呆)：限制只能選擇「當日及未來日期」，避免預約過去時間。
・時段選單限制：限定營業時間內的固定梯次（10:00 - 18:00）。
・4 大座位區偏好：海景窗邊景觀區、沉浸吧檯、綠植戶外庭院、靜謐閱讀區。
・預約成功代碼：送出後即時產生 #RES-xxxx 憑證，並同步寫入後台管理系統！

即時預約資料流向 (Data Flow)
1 顧客填寫預約表單並送出
2 前端 JavaScript 驗證日期合法性並寫入 LocalStorage
3 後台管理介面立即同步更新，店員可維護「已確認 / 已入座 / 已取消」

Part 05 ｜ AI 開發歷程

AI Agent 開發過程與 Prompt 策略

關鍵 Prompt 指令工程

學生 Prompt 範例：

「我們是商業設計系學生，主題做海景精品咖啡廳『嶼光珈琲』。請幫我們設計符合大地色與浪花色系的視覺規範，除了顧客前台的菜單、購物車與測驗，必須建立一個『可實際新增、編輯、刪除菜單與訂位狀態的後台 CRUD 管理介面』，並確保修改後前台能即時雙向連動。」

Vibe Coding 敏捷協作心法

・多問、多試、多改：不追求一次到位，先請 AI 生成骨架，再逐步加入客製化商設細節。

・模組化拆解：將專題拆分為「品牌視覺 → 顧客前台 → 後台 CRUD → 響應式優化」四大階段逐步驗證。

・版本控制 Commit 紀錄：每完成一組核心功能或修復一個 bug，便及時 commit 並附上明確說明。

Part 05 ｜ AI 開發歷程

開發遭遇之技術挑戰與 AI 解決方案

挑戰一：後台狀態無法即時連動前台
解決方法：引入集中式 State 管理與 LocalStorage 事件回呼機制，當管理員按下「切換售完」或「新增品項」時，觸發 renderApp() 重新繪製前台，無需重新載入網頁。
挑戰二：手機端導航列與按鈕溢出破版
解決方法：重構 Flex 排版與 Tailwind 斷點，加入漢堡選單抽屜（Mobile Drawer）與分類標籤橫向滑動（overflow-x-auto），小螢幕操作順暢。
挑戰三：線上訂位缺少日期限制出現幽靈單
解決方法：於 JavaScript 動態注入 input.min = today，並在表單提交時進行防呆攔截，確保每筆預約皆為合法時段。

【期末必備要求】改善紀錄 01 / 03

實際改善紀錄一：手機版響應式抽屜導航重構

原本的問題 (Before)
在手機螢幕（寬度 < 640px）瀏覽時，頂部導航連結擠在同一列造成文字重疊，且菜單分類標籤過長超出螢幕右側產生橫向捲軸破版。
改了什麼 (Decision & Change)
1. 建立獨立的漢堡選單按鈕與折疊抽屜（Mobile Nav Drawer）。
2. 菜單分類採用 overflow-x-auto 與 shrink-0 橫向手勢滑動，保持頁面乾淨。
怎麼確認 (Verification)
驗證方式：開啟 Chrome DevTools 模擬 iPhone 14 (390px) 與 Pixel 7 視窗，點擊漢堡選單可順暢展開與關閉，分類標籤橫滑流暢無溢出。
【期末必備要求】改善紀錄 02 / 03

實際改善紀錄二：線上訂位系統時段邏輯與防呆驗證

原本的問題 (Before)
早期原型使用純文字輸入框與普通日期選擇器，測試時使用者可以預約過去的日期（如上個月），且可填寫打烊後的半夜時段，造成幽靈預約單。
改了什麼 (Decision & Change)
1. 增加 JavaScript 動態鎖定 dateInput.min = today。
2. 將自由輸入時段改為固定營業時間下拉選單（10:00 - 18:00）。
3. 成功後彈出完整預約序號與座位區域憑證。
怎麼確認 (Verification)
驗證方式：實測日曆組件，昨日及以往日期呈灰色禁用狀態無法點選；送出測試預約單後，代號立即產生並於後台即時現身。
【期末必備要求】改善紀錄 03 / 03

實際改善紀錄三：後台 CRUD 與前台菜單庫存即時連動

原本的問題 (Before)
初版後台管理介面修改品項價格或切換「售完」狀態後，前台選單不會更新，必須手動 F5 重新整理頁面，購物車也無法辨別已售完品項而造成超賣。
改了什麼 (Decision & Change)
1. 建立共用 state 狀態中心與 saveData() 同步機制。
2. 庫存切換時即時更新卡片並將「點餐」按鈕設定為 disabled。
3. 新增品項立即在前台菜單與分類計數中生效。
怎麼確認 (Verification)
驗證方式：在後台將「耶加雪菲」切換為「已售完」，返回前台查看該品項立即標上 Sold Out 紅標且點餐按鈕鎖定；再次切換回供應中立即解鎖。
